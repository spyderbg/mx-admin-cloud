● Regenerating a voice now adds a new take instead of overwriting
  the old one, so you can keep several and pick the best by
  listening. The backend suite passes (639 tests), pylint is
  10/10, and the frontend voice tests (14), type-check and build
  pass. I didn't run the app or the Playwright e2e suite, and
  nothing is committed.

  The storage format needed no change: each language already had a
  main voice plus numbered variants, each with a metadata
  sidecar, and optimize already added variants. Four things were
  in the way:

  - Regenerate overwrote the file. POST .../voices/{id}/regenerate
    now writes a new numbered take (apple_en_02.mp3). The current
    main voice stays in use, and is first saved as a variant if
    it wasn't one already. The response is the new take. A
    language with no recording yet still gets its first take as
    the main voice.
  - Set-main could lose the first take. A new item has only the
    main file, and choosing a variant copied over it. Set-main now
    saves the outgoing main as a variant first.
  - The UI kept Optimize disabled. The backend sent no
    capabilities, so the UI showed "not available yet". GET
    .../voices now sends capabilities: selection is on, optimize
    is on while a voice optimizer is active, and generate, presets
    and multiple uploads stay off. I ran the API sync and
    regenerated the TypeScript client and schema.
  - UI copy said the audio gets replaced. The regenerate-all
    dialog (in English, Spanish, French and Bulgarian) and the
    regenerate toasts now say a new take is added and you choose
    it in Voices. I wrote the three translations myself, so check
    them.

  I also updated frontend/docs/item-voices-api.md and added tests
  for the take workflow and the capabilities response.

  What you'll see:
  - After regenerating, the played voice doesn't change until you
    choose the new take in the Voices section.
  - The optimize button is enabled, but optimized takes show up as
    separate cards, not the Original/Optimized tabs from the mock
    preview. The API doc lists adapting that as separate work.
  - Regenerate-all now creates one extra file per language each
    time it runs.
  - The optimize flag comes from the local voice-optimizer
    service. If your optimizers run on another host, the flag will
    read false even though optimizing works, the same limitation
    the existing voice-generation check has.

  What I left out, as agreed: the /generate and /presets
  endpoints, and automatic accuracy scoring. If you later want
  scoring, the existing /internal/evaluators/evaluate doesn't fit,
  because it's pipeline-shaped and writes into the pipeline's
  score stores.
